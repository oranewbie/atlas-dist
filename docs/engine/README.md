# atlas-engine — 그래프 실행 엔진

> 현재 버전 **v0.1.3** (프리뷰) · 다운로드: [Releases](https://github.com/oranewbie/atlas-dist/releases) 의 `engine-v*` 태그
>
> 이어서 읽기: [그래프 만들기 가이드](graph-guide.md) · [API·설정 레퍼런스](reference.md)

## 한 줄로 말하면

**"작업 상자들을 선으로 이어 두면, 순서대로(또는 동시에) 대신 돌려 주는 실행기"** 예요.

데이터를 읽고 → 가공하고 → 계산하고 → 결과를 내는 일을 떠올려 보세요. 각 단계를 상자(**노드**)로,
단계 사이의 흐름을 화살표(**엣지**)로 그린 것이 **그래프**예요. atlas-engine 은 이 그래프를 받아서
각 상자를 알맞은 순서로 실행하고, 앞 상자의 결과를 다음 상자에 넘겨 줘요.

- 상자 안의 일은 **Python 스크립트**로 직접 쓸 수 있어요(엔진에 들어 있는 기본 상자도 있어요).
- 화살표는 단순한 "다음으로"뿐 아니라 **조건 분기, 반복, 합류, 되돌아가기(루프)** 도 표현해요.
- 실행 중에 **멈추고, 이어 하고, 취소했다가 나중에 다시 불러올** 수 있어요.
- Claude 같은 **AI 에이전트가 직접 그래프를 만들고 돌릴 수 있도록** MCP 인터페이스를 제공해요.

엔진은 Rust 로 만들어져 가볍고 빠르고, 설치하면 실행 파일 하나로 동작해요.

## 이런 데 써요

| 활용 | 예 |
|---|---|
| **데이터 처리 파이프라인** | 파일·DB 에서 읽기 → 정제 → 집계 → 보고서 파일 쓰기 |
| **반복 처리(배치)** | 목록의 항목 100개를 하나씩, 또는 동시에 처리하고 결과 모으기 |
| **조건이 있는 업무 흐름** | "검증에 통과하면 A, 아니면 B" / "될 때까지 3번 재시도" |
| **AI 워크플로** | AI 호출 노드와 일반 계산 노드를 섞은 파이프라인, AI 가 직접 그래프를 짜서 실행 |
| **오래 걸리는 작업** | 중간에 멈췄다가 이어 하기, 취소한 지점부터 다시 시작 |
| **예측·분석** | 내장 노드 `demand_forecast`(이동평균 수요 예측) 같은 계산 단계 |

> **Atlas Studio 를 쓰신다면** 엔진을 직접 다룰 일은 거의 없어요. Studio 의 **그래프 편집기**가
> 엔진 설치·기동·실행·디버그를 대신해 주거든요. 이 문서는 엔진만 따로 쓰거나, 내부가 궁금한 분을 위한 거예요.

## 핵심 개념 — 공장 라인으로 비유하면

| 개념 | 뜻 | 비유 |
|---|---|---|
| **그래프** | 노드와 엣지를 담은 JSON 문서 | 생산 라인 설계도 |
| **노드** | 일 하나를 하는 단위 | 작업대 |
| **엣지** | 노드의 결과를 다음 노드로 넘기는 연결 | 컨베이어 벨트 |
| **super-step** | 실행의 한 박자. 이번 박자에 받을 물건이 있는 노드들이 **동시에** 일하고, 결과는 다음 박자로 넘어가요 | "땡!" 하면 모든 작업대가 한 번씩 일하는 방식 |
| **런타임** | 노드 종류(`node_type`)를 실제 실행기에 연결하는 등록 정보 | 작업대마다 배치된 직원 명부 |
| **워커 풀** | 미리 띄워 둔 Python 프로세스들. 노드마다 새로 켜지 않아 빨라요 | 대기 중인 상주 직원 |
| **이벤트** | 실행 중에 실시간으로 흘러나오는 소식(시작·완료·실패·진행 메시지) | 라인 방송 |
| **서브그래프** | 노드 안에 또 하나의 그래프를 넣은 것 | 작업대 안의 작은 라인 |

실행은 이렇게 흘러가요.

```
박자 0: 들어오는 화살표가 없는 "시작 노드"들이 일한다
박자 1: 그 결과를 받은 노드들이 동시에 일한다
박자 2: ...
끝:     더 넘길 결과가 없거나, 최대 박자 수(기본 30)에 닿으면 멈춘다
```

노드가 `null`(아무것도 없음)을 돌려주면 그 뒤로는 흐름이 멈춰요. 루프가 끝없이 돌지 않도록
최대 박자 수(`max_supersteps`)가 안전장치 역할을 해요.

## 설치

### 1. 받기

[Releases](https://github.com/oranewbie/atlas-dist/releases) 에서 `engine-v<버전>` 을 찾아 내 PC 에 맞는 파일을 받아요.

| OS | 파일 |
|---|---|
| Windows (x64) | `atlas-engine-bundle-<버전>-win-amd64.zip` |
| Linux (x64) | `atlas-engine-bundle-<버전>-linux-amd64.tar.gz` |

macOS 번들은 아직 없어요.

### 2. 준비물

- 엔진 자체는 실행 파일이라 따로 필요한 게 없어요.
- **Python 3.10 이상** — Python 노드를 쓰려면 필요하고, 설치 스크립트도 Python 으로 돌아가요.
- (선택) **uv** — 노드별 가상환경(venv)을 엔진이 자동으로 만들게 하려면 PATH 에 있어야 해요.

### 3. 설치와 실행

압축을 풀고, 그 폴더에서 실행해요. **압축을 푼 폴더가 곧 설치 위치**예요.

```powershell
# Windows
.\install.ps1          # 설정 파일 준비 (처음 한 번)
.\run\engine.ps1       # 엔진 시작
```

```sh
# Linux
./install.sh
./run/engine.sh
```

잘 떴다면 콘솔에 이런 줄이 보여요.

```
atlas-engine starting  addr=127.0.0.1:50051 ...
MCP enabled endpoint=http://127.0.0.1:50151/mcp
```

| 접속 창구 | 기본 주소 |
|---|---|
| gRPC (프로그램용) | `127.0.0.1:50051` |
| MCP (AI 에이전트용) | `http://127.0.0.1:50151/mcp` |

기본값은 **내 PC 에서만 접속**할 수 있게 열려요. 지금 버전에는 인증 기능이 없으니,
다른 PC 에서 접속하도록 열 때(`0.0.0.0`)는 믿을 수 있는 네트워크에서만 쓰세요.

### 번들 안에 든 것

```
atlas-engine-bundle-<버전>-<os>-<arch>/
├─ bin/        atlas-engine(.exe)       ← 엔진
│              atlas-engine-mcp(.exe)   ← AI 클라이언트용 MCP 브리지
├─ workers/    worker_io.py · scriptable_function.py   ← Python 노드 도우미
├─ conf/       default/atlas-engine.toml               ← 설정
├─ run/        engine.ps1 · engine.sh                  ← 시작 스크립트
└─ install.py · install.ps1 · install.sh
```

### Atlas Studio 로 설치하기 (더 쉬운 방법)

Studio 를 쓰고 있다면 **설정 ⚙ › 환경 설정 › 구성 요소 › 그래프 엔진** 카드의 **[설치]** 를 누르거나,
통합 터미널에서 `atlas engine install` 을 실행하면 돼요. 설치 위치는 `~/.atlas/engine` 이고,
그래프를 실행할 때 엔진이 꺼져 있으면 Studio 가 알아서 켜요.

## AI 에이전트에게 엔진 쥐여 주기 (MCP)

엔진은 AI 에이전트가 쓸 수 있는 **도구 묶음(MCP 서버)** 도 함께 제공해요. 연결해 두면 에이전트가
노드를 검색하고, 그래프를 짜고, 실행하고, 결과를 보면서 고치는 일을 스스로 해요.

```sh
# Claude Code 에 연결 (엔진이 떠 있어야 해요)
claude mcp add --transport http atlas-engine http://127.0.0.1:50151/mcp
```

에이전트가 쓰는 도구 중 `guide` 를 부르면 엔진 사용 설명서가 나와요. 에이전트는 이걸 먼저 읽고 일을 시작해요.
자세한 연결 방법은 [레퍼런스 › MCP](reference.md#mcp--ai-에이전트용-창구) 를 보세요.

Studio 에서는 엔진을 설치하면 MCP 서버가 `atlas-engine` 이라는 이름으로 **꺼진 채** 등록돼요.
툴 패널 › MCP 서버에서 켜거나 `atlas mcp enable atlas-engine` 으로 켜면 돼요.

## 지금 할 수 있는 것 / 아직 못 하는 것

프리뷰 버전이라 솔직하게 정리해 둘게요.

**할 수 있어요**
- 순환(루프)을 포함한 그래프 실행, 6가지 연결 방식(데이터·조건·반복·병렬 반복·합류·설정)
- 서브그래프 중첩
- Python 노드(상주 워커 풀)와 내장 노드를 한 그래프에서 섞어 쓰기
- 일시정지·재개, 취소 후 다시 불러오기, 중단점, 실시간 이벤트 스트리밍
- gRPC API, MCP(HTTP·stdio), Java·Python SDK
- 노드별 Python 가상환경 자동 준비(uv), 오프라인 설치(wheelhouse)

**아직 안 돼요 / 제약이 있어요**
- 실행할 때 입력값을 따로 넣을 수 없어요 → 시작 노드의 `params` 에 넣어 주세요.
- 엔진을 다시 시작하면 **진행 중이던 실행은 사라져요**(취소해서 저장해 둔 실행만 남아요).
- 인증·권한 기능이 없어요. Python 노드는 내 PC 권한 그대로 실행되니 믿을 수 있는 코드만 넣어 주세요.
- 내장 노드는 3개뿐이에요(`demand_forecast`, `rust_echo`, `counter`). 나머지는 Python 노드로 만들어요.
- macOS 번들, 분산 실행, 스케줄러는 아직 없어요.
