# Atlas Studio 활용 사례

> Atlas Studio 는 **"순서가 있고, 결과물이 있고, 되풀이되는 일"** 이라면 어디에나 쓸 수 있어요.
> 코딩을 몰라도 돼요. 아래는 분야별로 "어떻게 담으면 되는지"를 보여 주는 예시예요.
> 개념이 낯설면 [소개](README.md) 와 [용어집](glossary.md) 을 먼저 보세요.

## 시작하는 방법은 어디서나 같아요

1. 빈 폴더로 **새 프로젝트**를 만들어요.
2. 챗에 **"○○ 일을 하는 작업 파이프라인을 설계해 줘"** 라고 말해요.
   AI 가 무슨 일을, 어떤 단계로, 무엇을 기준으로 끝낼지 물어보고 단계(Stage)와 작업(Activity)을 만들어 줘요.
3. 작업을 실행해 보고, 결과가 아쉬우면 **"이 결과를 보고 절차를 고쳐 줘"** 라고 해요.
4. 쓸 만해지면 그 방법을 **템플릿**으로 남겨 다음 프로젝트에서 바로 시작해요.

---

## 1. 정기 보고서·문서 만들기

**이런 일**: 주간 보고, 월간 실적 정리, 회의록 정리, 고객사 보고서

| 단계 | 하는 일 |
|---|---|
| ① 재료 모으기 | 한 주의 메모·메일 내보내기·엑셀을 폴더에 넣어요 |
| ② 초안 쓰기 | AI 가 절차서("성과/계획/리스크 세 절로…")대로 초안을 만들어요 |
| ③ 검토 | 검토 작업이 기준에 맞는지 점검하고 부족한 점을 적어요 |
| ④ 다듬기 | 지적 사항을 반영하고, 절차서도 함께 고쳐요 |

- 작업에 **입력 폼**을 달면 실행할 때마다 "몇 주차?" 같은 값을 물어봐요.
- 자주 쓰는 작업은 **챗 입력창의 `/`** 로 바로 실행해요.
- 결과 문서는 **미리보기**로 인쇄될 모양 그대로 확인해요.
- → [쉽게 따라하기](tutorial.md) 가 바로 이 예제예요.

## 2. 많은 대상을 같은 방법으로 처리하기

**이런 일**: 화면 200개 점검, 계약서 50건 요약, 상품 설명 300개 정리, 고객 문의 분류

- **작업 목록**에 대상을 쭉 넣어요(직접 추가하거나 "이 폴더의 파일로 작업 목록을 구성해 줘").
- **작업 지시서**에 "어떻게 할지"를 한 번만 써요. 모든 대상이 같은 지시서를 함께 써요.
- 대상을 체크하고 **[실행]** — 하나씩 차례로 처리하고, 하나가 실패해도 다음으로 넘어가요.
- 대상마다 상태·진척이 보이고, 이번에 안 할 대상은 **사용 끔**으로 치워 둘 수 있어요.
- 각 실행은 **실행 기록**에 남아서 나중에 무엇이 어떻게 됐는지 확인할 수 있어요.
- AI 가 많은 항목을 **서브에이전트**에게 나눠 맡기기 때문에 긴 배치에서도 대화가 흐려지지 않아요.

## 3. 시스템 전환·구축 프로젝트 운영

**이런 일**: 옛 시스템을 새 기술로 옮기기(마이그레이션), 신규 시스템 구축, 표준화 작업

실제로 이런 프로젝트에서 Studio 가 쓰이고 있어요. 예를 들어 화면 전환 프로젝트라면:

```
S1 소스 분석 → S2 전환 방침 → S3 전환 규칙 → S4 화면 전환(화면마다 반복) → S5 검증·인수
```

- 방법론 문서로만 있던 절차가 **단계 + 작업 절차서 + 도구**로 프로젝트 안에서 실제로 돌아가요.
- 화면 하나하나를 작업 목록 항목으로 두고 같은 전환 절차를 걸어요.
- **Flow** 로 "전환 → 검증 → 실패하면 다시 전환(최대 3번)" 같은 흐름을 그려요.
- 팀원 모두가 같은 `.atlas/` 폴더를 git 으로 공유하니, 사람과 AI 가 **같은 방법**으로 일해요.
- 한 프로젝트에 **워크벤치를 여러 개** 둘 수 있어요(예: 분석·설계용, 전환 구현용).
- 프로젝트가 끝나면 다듬어진 방법론을 **템플릿으로 추출**해서 다음 전환 프로젝트의 출발점으로 써요.

## 4. 문서화 — 있는 것을 설명서로

**이런 일**: 오래된 시스템의 사용 설명서 만들기, 인수인계 문서, 신규 입사자용 안내

- 내장 작업 **소스 매뉴얼화**: 폴더·화면·기능 하나를 지정하면 AI 가 읽고 개요·용어·구조·사용법·설정·주의점을
  정리한 문서를 만들어요. 독자(개발자 / 사용자 / AI)를 고를 수 있어요.
- 만든 문서는 프로젝트 **위키**(`.atlas/wiki/`)에 쌓이고, 나중에 AI 도 사람도 검색해서 참고해요.
- 기존 문서를 함부로 고치지 않고 "이렇게 고치면 좋겠다"는 **갱신 제안**만 남겨요.

## 5. 데이터 정리·분석

**이런 일**: 엑셀·CSV 집계, 로그 분석, 정기 데이터 가공

- atlas-agent 백엔드를 쓰면 AI 가 폴더의 **CSV·엑셀·Parquet** 를 복사 없이 바로 SQL 로 집계해요.
- 한 줄에 레코드 하나인 `.jsonl` 이나 레코드 배열 `.json` 은 Studio 에서 **표로 열어** 정렬·필터해 볼 수 있어요.
- 매번 같은 가공을 한다면 **그래프 편집기**로 "읽기 → 정제 → 집계 → 저장" 파이프라인을 Python 노드로 만들어
  버튼 하나로 돌려요. (→ [atlas-engine](../engine/README.md))
- 결과는 툴의 **표·차트 화면**으로 챗 안에 띄워 볼 수도 있어요.

## 6. 웹 서비스 테스트·문제 진단

**이런 일**: 웹 화면 테스트, "버튼이 안 먹어요" 같은 문의 원인 찾기, 화면 명세 작성

- **브라우저 확장**(Chrome·Edge)을 깔면 웹 페이지 옆에 AI 챗이 붙어요.
- AI 가 화면을 읽고, 클릭·입력하고, **네트워크 요청과 콘솔 오류**까지 함께 봐요 —
  "API 가 500 을 돌려줬다", "스크립트 오류가 났다" 같은 숨은 원인을 찾아요.
- **관련 소스 찾기**로 지금 화면을 이루는 소스 파일을 찾아 기록해 두면, 다음부터 그 화면에서 바로 소스를 열어요.
- [atlas-react](../react/README.md) 로 만든 화면이라면 화면이 등록한 기능을 AI 가 직접 실행하며 테스트해요.

## 7. 반복 업무·운영 체크리스트

**이런 일**: 배포 전 점검, 월말 마감 절차, 정기 점검표

- 체크리스트 항목을 작업(Activity)으로 만들고, **선행 조건**(앞 작업이 끝나야 실행)을 걸어요.
- 프로그램으로 확인할 수 있는 건 **터미널 명령·툴 실행** 작업으로 두면 사람 없이 돌고, 결과(✓/✗)가 기록돼요.
- 판단이 필요한 건 AI 작업으로, 최종 확인은 사람이 결과물을 보고 해요.

## 8. 지식 쌓기 — 팀과 나

| 무엇을 | 어디에 | 예 |
|---|---|---|
| 팀이 알아야 할 사실 | **메모리** (`.atlas/memory/`) | "운영 DB 는 매주 일요일 점검" |
| 늘 지킬 규칙 | **AGENT.md** | "보고서는 항상 존댓말, 숫자는 천 단위 쉼표" |
| 일하는 요령 | **가이드** | "고객 문의 분류할 때는 이렇게" |
| 정리된 문서 | **위키** (`.atlas/wiki/`) | 분석 결과, 설계 문서 |
| 나만의 메모 | **개인 노트** (`~/.atlas/notes/`) | 아이디어, 참고 링크, 데일리 노트 |

AI 에게 "이건 앞으로 항상 이렇게 해 줘", "위키에 정리해 줘", "내 노트에 적어 둬"라고 말하면 알맞은 곳에 적어요.
개인 노트는 **Obsidian 과 같은 형식**이라 같은 폴더를 Obsidian 에서도 열 수 있어요.

## 9. 소프트웨어 개발

물론 개발에도 좋아요.

- VS Code 스타일 편집기·탐색기·검색·통합 터미널, 디버거(Node/TS·Python·Java + 사용자 추가), 정의로 이동
- AI 가 고친 파일은 **변경 이력**에 남고, 이 대화에서 고친 파일 목록을 따로 볼 수 있어요.
- 코드를 고치는 Flow 는 **격리 실행(git worktree)** 으로 원본을 건드리지 않고 돌린 뒤 성공하면 합칠 수 있어요.
- "테스트가 통과할 때까지 고치기" 같은 루프를 Flow 의 **되돌아가기** 연결로 표현해요.

## 내 일을 담을 때 생각할 세 가지

| 질문 | Studio 에서 |
|---|---|
| **무엇을** 처리하나? | 대상이 여럿이면 → 작업 목록 |
| **어떤 순서로** 하나? | 단계(Stage)와 작업(Activity), 필요하면 Flow |
| **언제 끝난 것**인가? | 결과 파일, 검토 작업의 판정, 선행 조건 — 그리고 마지막엔 사람이 확인 |

막히면 챗에 그대로 물어보세요. AI 가 Studio 의 사용법 가이드를 읽고 답해요.
