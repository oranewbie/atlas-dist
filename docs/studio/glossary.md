# Atlas Studio 용어집

> Studio 에서 쓰는 말을 쉽게 풀어 둔 사전이에요. 처음이라면 [소개](README.md) → 이 용어집 → [쉽게 따라하기](tutorial.md) 순서를 권해요.

## 빠른 지도

```
Atlas Studio (앱)
└─ 프로젝트 = 내 폴더 + .atlas/
   └─ 워크벤치 (일하는 방법 묶음 — 여러 개 가능, 그중 하나가 "활성")
      └─ Stage (단계)
         └─ Activity (작업 하나 = 실행 단위)   ← AI 또는 프로그램이 수행

작업 목록의 항목 (무엇을)  ×  작업 지시서 (어떻게)  =  실행 한 번
툴 (AI 가 쓰는 도구)  ·  챗 (화면마다 붙는 AI)
```

---

## 1. 프로젝트와 워크벤치

**프로젝트** — 작업 폴더 하나예요. 실제 재료(문서·소스·데이터)는 폴더 전체이고, Studio 의 정보는 전부 그 안의 `.atlas/` 에
  **파일로** 저장돼요. 서버나 데이터베이스가 없어서 팀 공유는 git 같은 버전 관리로 폴더를 나누면 끝이에요.

**`.atlas/` (프로젝트 홈)** — Studio 정보가 사는 폴더. **바로 아래는 팀 공유**, **`private/` 아래는 나만** 보는 것이에요.
  "누가 언제 무엇을 했나(이력)"는 비공개, "무엇이 나왔나(산출물)"는 공유가 원칙이에요.

**워크벤치** — **"이 일을 하는 방법"** 의 묶음이에요 — 단계, 작업 절차서, 도구, 안내문.
  코드가 아니라 파일 묶음이라 프로젝트를 하면서 자라고, 잘 자라면 템플릿으로 꺼내 다른 프로젝트에 쓸 수 있어요.

**활성 워크벤치** — 한 프로젝트에 워크벤치를 여러 개 둘 수 있고, 화면은 그중 **지금 고른 하나**를 보여 줘요.
  타이틀바의 `🔧 <이름> ▾` 에서 바꿔요. 바꿔도 다른 워크벤치의 내용은 그대로 남아요.

**워크벤치 템플릿** — 다 자란 워크벤치에서 실행 이력 같은 프로젝트 고유 정보를 뺀 재사용본이에요. 등록해 두면
  설정 ⚙ › 프로젝트 › 워크벤치 › **[워크벤치 선택…]** 에서 골라 새 프로젝트에 바로 적용해요.

**앵커 (`.atlas/project.yaml`)** — "이 폴더는 Atlas 프로젝트다"라는 표시 파일. 프로젝트 이름과 활성 워크벤치를 담아요. 직접 고치지 마세요.

## 2. 일을 나누는 단위

**Stage (단계)** — 일을 크게 나눈 단계예요(예: 재료 모으기 → 초안 → 검토). Activity 화면의 **탭 하나가 단계 하나**이고,
  작업을 묶는 이름표 역할을 해요.

**Activity (작업)** — 단계 안에서 **실제로 실행하는 일 하나**예요. "Task" 라고도 불러요(같은 말). 실행 방식은 등록할 때 정하고 바꿀 수 없어요.

| 실행 방식 | 뜻 |
|---|---|
| **Skill 구성** | AI 가 절차서(skill.md)대로 수행해요 |
| **Run (터미널)** | 명령을 통합 터미널에서 실행해요 |
| **Debug 실행** | 디버거로 프로그램을 실행해요 |
| **Tool call** | 등록된 툴을 실행해요 |
| **Flow** | 여러 작업을 정해진 흐름대로 이어서 실행해요 |

**절차서 (skill.md, 스킬)** — AI 가 따르는 작업 방법 문서예요. "AI 에게 매번 같은 설명을 반복하는 대신 방법을 문서로 굳힌 것"이에요.
  맨 위의 한 줄 소개(description)를 잘 써 두면 AI 가 알맞은 스킬을 잘 찾아요.

**입력 폼** — 작업을 실행할 때 먼저 물어볼 값(대상, 주차, 옵션…). ▶ 를 누르든, 챗 `/` 로 고르든, 명령으로 돌리든 같은 폼이 떠요.

**선행 조건 (게이트)** — "앞 작업이 끝나야 이 작업을 할 수 있다"는 조건이에요. 조건이 안 맞으면 실행이 막히고 **⏸ 선행 대기**로 보여요.
  그 밖의 "충분히 잘 됐나" 판단은 사람이 결과물을 보고 해요.

**Flow (실행 흐름)** — 여러 작업을 선으로 이은 **일의 순서**예요. "검증이 실패하면 다시 구현(최대 3번)" 같은 되돌아가기도 그려요.
  단계 화면 오른쪽의 **Flow 탭**에서 그려요.
  ⚠️ **그래프 편집기의 실행 그래프와는 달라요** — Flow 는 *일의 순서*, 실행 그래프는 *데이터 계산 파이프라인*이에요.

**내장 작업** — 만들지 않아도 늘 있는 작업이에요. 지금은 **가이드 물어보기**(Studio 사용법 질문에 답하기)와
  **소스 매뉴얼화**(폴더·화면 하나를 읽고 설명서 만들기) 두 가지예요.

## 3. 많은 대상 다루기

**작업 목록 / 작업 항목** — 이 프로젝트가 처리할 **대상**의 목록이에요 — 화면, 문서, 고객, 할 일… 프로젝트마다 단위가 달라요.
  항목 하나하나가 진척을 세는 단위예요.

**작업 지시서** — "이 일을 **어떻게** 할 것인가" 한 장이에요. 어떤 작업(또는 Flow)을 쓸지와 지시 내용을 담고, 여러 대상이 함께 써요.
  **대상(무엇) × 지시서(어떻게) = 실행 한 번**.

**챗 위임 / 헤드리스 실행** — 지시서가 AI 작업을 쓰면 **챗 위임**(AI 대화로 진행, 사람이 보는 앞에서), 프로그램·명령 작업을 쓰면
  **헤드리스 실행**(사람 없이 돌고 ✓/✗ 기록)이에요. 연결한 작업이 정해요.

**사용 끔** — 목록에 남겨 두되 이번엔 하지 않을 항목. 흐리게 보이고 실행 대상으로 고를 수 없어요.

**실행 기록 (잡 레코드)** — 실행 한 번마다 남는 기록(`.atlas/jobs/`). 무엇이 왜 돌았고 어떻게 끝났는지 **실행 기록** 화면에서 봐요.

## 4. AI 와 지식

**챗 / 대화** — 챗 창의 대화 하나. 화면을 옮겨도 이어지고, 매 메시지마다 **지금 보는 화면 상태**가 AI 에게 함께 전달돼요.

**에이전트 (역할)** — 대화를 연 화면에 따라 AI 의 역할이 정해져요.

| 이름 | 어디서 | 하는 일 |
|---|---|---|
| **Atlas Agent** | 일반 화면 | 무엇이든 묻는 기본 도우미 |
| **Stage Agent** | 단계 탭 | 그 단계를 책임지고 진행 |
| **Graph Agent** | 그래프 편집기 | 데이터 파이프라인 구성·실행·진단 |
| **Tool Builder** | 툴 패널 | AI 가 쓸 도구 만들기 |
| **Skill Builder** | 작업 편집 | 절차서 만들기 |
| **Workbench Builder** | 워크벤치 설계 | 방법론 설계, 템플릿 만들기 |
| **Atlas Bridge Agent** | 브라우저 확장 | 웹 화면 테스트·조작 |

**백엔드** — AI 를 실제로 돌리는 엔진이에요. **Claude Code**(기본) 또는 **atlas-agent**(여러 모델·사내 모델) 중 골라요.

**에이전트 프로파일** — "백엔드 + 모델" 조합에 이름을 붙인 것. 작업마다 다른 AI 를 쓰고 싶을 때 이름으로 지정해요.

**서브에이전트** — AI 가 큰 일을 쪼개 따로 맡기는 보조 AI. 세부 과정은 접힌 블록으로만 보이고, 메인 대화에는 요약만 돌아와요.

**지식의 종류**

| 종류 | 무엇을 담나 | 어디에 |
|---|---|---|
| **메모리** | 기억할 **사실** (한두 문단) | `.atlas/memory/` (팀) · `.atlas/private/memory/` (나만) |
| **지시서 (AGENT.md)** | 항상 지킬 **규칙** | `.atlas/AGENT.md` |
| **가이드** | ~할 때 **어떻게** 하나 (절차·요령) | 제품 내장 + 워크벤치 `guides/` |
| **위키** | X 가 **무엇이고 왜** (분석·설계·설명서) | `.atlas/wiki/` |
| **대화 기록** | 대화 원문 | `.atlas/private/agent/chats/` |
| **개인 노트** | 프로젝트와 무관한 나만의 메모 | `~/.atlas/notes/` |

## 5. 도구

**툴** — AI 가 부르는 프로젝트 도구예요. 툴 패널(🛠)에서 관리해요.

| 종류 | 뜻 |
|---|---|
| `code` | 프로그램(코드)으로 일하는 도구 |
| `form` | 사용자에게 폼을 띄워 답을 받아 오는 도구 — 코드 없이 선언만으로 |
| `render` | 표·차트·문서 같은 화면을 보여 주는 도구 — 코드 없이 선언만으로 |

**내장 도구** — 등록하지 않아도 AI 가 늘 쓰는 능력 — 파일 읽기·쓰기, 명령 실행, `atlas` 명령, Studio 화면 열기·새로 고침, 메모리 저장 등.

**MCP 서버** — 바깥 도구 서버를 연결하는 표준 방식이에요. 등록하면 새 대화부터 그 도구가 AI 에게 붙어요.

## 6. 그 밖에

**실행 그래프 / 노드 클래스 / Python 환경** — 그래프 편집기에서 만드는 **데이터 계산 파이프라인**, 그 안의 상자 종류(Python 소스로 정의), 상자가 쓸 패키지 묶음(venv).
  실행은 [atlas-engine](../engine/README.md) 이 해요.

**변경 이력 / 타임라인** — 파일이 저장될 때마다 남는 버전 기록. 사람이 고쳤든 AI 가 고쳤든 남고, 이전 버전과 비교하거나 되돌릴 수 있어요.

**실행 구성 (launch config)** — 프로그램을 어떻게 실행·디버그할지 적은 파일(`.atlas/launch.yaml`, `.vscode/launch.json` 도 읽어요).

**브라우저 확장** — Chrome·Edge 옆에 붙는 Studio 챗. 웹 페이지를 보고, 누르고, 네트워크·콘솔까지 읽어요.

**플러그인** — Studio 에 화면·명령을 더하는 설치형 꾸러미. 그래프 편집기와 개인 노트가 내장 플러그인이에요.
