## 1. 설치와 업데이트

### 설치

- [Releases](https://github.com/oranewbie/atlas-dist/releases) 에서 최신 `studio-v<버전>` 의 **`…-setup.exe`** 를 받아 실행해요.
- Node 와 필요한 부품이 모두 들어 있어서 따로 준비할 건 없어요.
- 서명되지 않은 설치 파일이라 SmartScreen 경고가 뜨면 **추가 정보 → 실행** 을 눌러요.

같은 릴리스에 있는 다른 파일은 Studio 가 필요할 때 알아서 받아 써요.

| 파일 | 용도 |
|---|---|
| `atlas-browser-bridge.zip` | 브라우저 확장 (§14) |
| `atlas-java-debug.tar.gz` | Java 디버그 어댑터 (§8) |

### AI 준비

| 백엔드 | 준비 |
|---|---|
| **Claude Code** (기본) | 터미널에서 `claude` 로 로그인(또는 `claude setup-token`). Studio 는 로그인을 대신하지 않고, 저장·전환만 관리해요 |
| **atlas-agent** | 설정 ⚙ › 환경 설정 › 에이전트에서 백엔드를 바꾸고, **Config** 로 모델 설정. 설치·실행은 자동이에요 ([atlas-agent 설정](../agent/configuration.md)) |

### 업데이트

- 새 버전이 나오면 **아래 상태바에 한 번** 알림이 떠요. ✕ 로 끄면 그 버전은 다시 묻지 않아요.
- 직접 확인하려면 **도움말 › 업데이트 확인**.
- [설치]를 누르면 새 설치 파일을 받아 실행하고 앱이 닫혀요.

## 2. 프로젝트 시작하기

### 새 프로젝트

타이틀바 **프로젝트 › 새 프로젝트…**. 묻는 건 **프로젝트명 · 폴더 · 작업자** 뿐이에요.

- **프로젝트명이 곧 폴더 이름**이에요. [찾아보기]로는 **상위 폴더**를 고르고, 그 아래에 프로젝트명 폴더가 생겨요.
- 이미 있는 폴더 이름이면 빨갛게 표시되고 완료할 수 없어요. 이름이나 위치를 바꾸세요.
- 만들어지는 건 **빈 워크벤치**(단계 0개)예요. 정해진 방법론(템플릿)으로 시작하고 싶으면 프로젝트를 연 뒤
  **설정 ⚙ › 프로젝트 › 워크벤치 › [워크벤치 선택…]** 에서 골라요.

### 기존 폴더 열기

**프로젝트 › 폴더 열기…** 로 열어요. 최근 프로젝트는 시작 화면에 있고, 마지막 프로젝트는 다음 실행 때 자동으로 열려요.
코드 저장소든 문서 폴더든 아무 폴더나 열 수 있어요.

### `.atlas/` 폴더 — 모든 정보가 여기에

Studio 는 서버나 DB 를 쓰지 않아요. 모든 정보가 프로젝트 안의 `.atlas/` 에 **파일로** 있어요.

```
<프로젝트>/.atlas/            ← 바로 아래는 모두 팀이 공유 (git 으로 그대로)
├─ project.yaml               앵커 — 프로젝트명·활성 워크벤치
├─ AGENT.md                   AI 가 이 프로젝트에서 항상 지킬 규칙
├─ memory/                    팀이 함께 쌓는 기억 (사실·결정·선호)
├─ skills/                    프로젝트 스킬
├─ wiki/                      작업 결과 문서
├─ jobs/                      실행 기록
├─ screens/  graphs/  launch.yaml  mcp.json  permission.json  agents.json
├─ workbenches/<id>/          워크벤치 (여러 개 가능) — stages/ · tools/ · results/ · reports/
├─ <팀이 만드는 무엇이든>       새 폴더를 만들면 그대로 공유돼요
└─ private/                   ← 나와 내 AI 만 (공유되지 않아요)
     agent/                   대화 원문·호출 기록·임시 파일
     memory/                  나만 보는 기억
     file-history/            파일 변경 이력
     ui/ runs/ …              개인 화면 상태·진행 중인 실행
```

- 원칙은 하나예요: **이력(누가 언제 무엇을 했나)은 비공개, 산출물(무엇이 나왔나)은 공유.**
- 팀 공유는 이 폴더를 그냥 git 에 올리면 돼요. `private/` 는 Studio 가 관리하는 `.atlas/.gitignore` 가 이미 막고 있어요
  (이 파일의 `# >>> atlas 공유 정책` 부분은 직접 고치지 마세요).

> 대화 원문에는 AI 가 읽은 파일 내용과 명령 결과가 통째로 들어가요. 옛 버전에서 만든 프로젝트라면 이미 커밋됐을 수 있으니
> 한 번 확인해 보세요: `git ls-files .atlas/private/agent/chats`

### 워크벤치 여러 개 — 골라서 진행

한 프로젝트에 워크벤치를 여러 개 둘 수 있어요(예: 분석·설계용 하나, 실제 작업용 하나). 화면은 **활성 워크벤치 하나**를 보여 줘요.

| 하는 일 | 어디서 |
|---|---|
| 바꾸기 | 타이틀바 프로젝트명 옆 **`🔧 <id> ▾`** — 목록에서 고르면(● = 지금 활성) 다시 읽어요 |
| 목록 보기·추가 | 피커 › **워크벤치 관리…** (= 설정 ⚙ › 프로젝트 › 워크벤치). [워크벤치 추가…]로 빈 워크벤치를 만들 때 **'워크벤치 구성' 가이드 포함**을 켜 두면 AI 가 방법론 인터뷰로 단계를 설계해 줘요 |
| 템플릿 적용 | 같은 화면 **[워크벤치 선택…]** — 등록된 템플릿을 골라 [적용하고 전환]. 받은 zip 은 **[워크벤치 템플릿 등록 (zip)…]** 으로 먼저 등록. 지금은 앱에 기본으로 들어 있는 템플릿이 없어서, 직접 만들거나(§5 끝 "템플릿으로 내보내기") 전달받은 zip 을 등록해 써요 |

- 바꾸면 **단계 탭·작업·작업 목록·툴**이 새 워크벤치 것으로 바뀌어요. 탐색기·찾기·변경 이력·실행 기록·터미널은 프로젝트 것이라 그대로예요.
- 바꾸는 건 **가리키는 것만 옮기는 것**이라 다른 워크벤치의 내용은 그대로 남아요.
- 이미 열려 있는 대화는 바꾸기 전 맥락을 써요. 바꾼 뒤엔 **새 대화**로 시작하는 게 정확해요.
- 지우려면 폴더(`.atlas/workbenches/<id>/`)를 지우면 돼요. 활성 워크벤치를 지우기 전엔 다른 것으로 먼저 바꾸세요.

## 3. 화면 구성

```
┌ 타이틀바   atlas · ← → ⟳ ⌂ · 프로젝트/파일/도움말 메뉴 · 프로젝트명(클릭 = 이름 편집) · 🔧 워크벤치 · 창 버튼
├ 본문
│  ├ 아이콘 바     왼쪽 — 화면 전환. 끌어서 순서 변경, 우클릭 = 보이기/숨기기, 맨 아래 ⚙ = 설정
│  ├ 메인 화면     지금 고른 화면 (다른 화면에 다녀와도 상태가 그대로)
│  ├ 하단 패널     터미널 · 로그 · 디버그 콘솔 · 문제   (Ctrl+` 로 열고 닫기)
│  └ 챗           AI 대화 — 위/아래/왼쪽/오른쪽에 붙이고 접었다 펼 수 있어요
└ 상태바        버전 · 업데이트 알림
```

### 아이콘 바

- 처음엔 **6개**만 보여요: **탐색기 · 찾기 · Run & Debug · 작업 목록 · Activity · 툴**.
- 플러그인이 더하는 아이콘(예: 개인 노트)이 그 뒤에 붙어요.
- **변경 이력 · 실행 기록 · 그래프 편집기**는 숨겨져 있어요. 아이콘 바를 **우클릭**해서 체크하면 나타나요(프로젝트에 저장돼요).
- 매일 쓰는 아이콘이 묻히지 않도록 일부러 줄여 둔 거예요.

### 명령 팔레트와 빠른 열기

- **`Ctrl+Shift+P` 명령 팔레트** — 모든 명령(이동·보기·파일·디버그·단계)을 검색해서 실행해요.
- **`Ctrl+P` 파일 빠른 열기** — 프로젝트 전체에서 파일을 찾아요.
  - 아무것도 안 치면 최근 연 파일부터 보여요.
  - 이름을 그대로 치면 그 파일이 맨 위로 와요(완전 일치 → 그 글자로 시작 → 포함 → 경로에 포함 순).
  - `shell/act` 처럼 **`/` 를 넣으면** 경로로 좁혀요. `.atlas` 처럼 점으로 시작하면 숨김 폴더도 바로 나와요.
  - 50개씩 보여 주고, 내리면 계속 이어져요. 아래에 `보이는 수 / 전체` 가 보여요.

### 앞뒤로 이동 (← → ⟳ ⌂)

- 타이틀바 왼쪽 버튼, `Alt+←` / `Alt+→` / `Alt+Home`, 마우스 뒤로·앞으로 버튼으로 **브라우저처럼** 다녀온 화면을 오가요.
- ⟳ 는 지금 화면 새로 고침(`Ctrl+R`), ⌂ 는 홈 화면이에요. 홈은 **설정 ⚙ › 프로젝트 › 홈 화면**에서 정해요(기본 Activity).
- 편집 화면 오른쪽 위의 **← 뒤로**는 조금 달라요 — 같은 단계 안에서 왔으면 그리로, 다른 화면을 다녀왔으면 한 단계 위(작업 목록)로 가요.

### 파일 메뉴와 새로 고침

- **파일 메뉴**에는 지금 화면이 지원하는 것(새로 만들기/열기/저장/닫기)만 나타나요.
- **`Ctrl+R`** 은 지금 화면 새로 고침이에요(없으면 프로젝트 다시 읽기). 앱 전체가 새로 고쳐지지 않으니 대화가 끊기지 않아요.

### 표(그리드) 공통 조작

작업 목록, Activity 목록 같은 표는 조작 방법이 같아요.

| 조작 | 방법 |
|---|---|
| 정렬 | 머리글 클릭 (오름 → 내림 → 해제) |
| 글자로 거르기 | 머리글 아래 칸에 입력 |
| 값 골라 거르기 | 필터 칸 오른쪽 **⋯** — 그 열에 실제로 있는 값 목록에서 체크 (여러 개, 검색, [모두], [지우기]) |
| 폭 · 순서 | 머리글 경계 끌기 · 머리글 끌기 |
| 열 숨기기 · 고정 | 오른쪽 위 **⚙** — 체크로 보이기/숨기기, **📌** 로 왼쪽 고정, "기본값으로" |

숨김·폭·순서·정렬·고정은 **이 PC 에 표마다** 저장돼요.

### 파일을 표·미리보기로 보기

| 파일 | 볼 수 있는 모양 |
|---|---|
| `.jsonl`(한 줄 = 한 레코드), 레코드 배열 `.json` | **원문 / 표** — 행을 누르면 아래에 원본 상세. 중첩 값은 `data.usage.output` 같은 열 |
| `.md` | **원문 / 미리보기** — 챗과 같은 모양으로 그려지고 링크가 동작해요 |
| `.html` · `.svg` | **원문 / 미리보기** — 스크립트를 끈 안전한 상자 안에서 그려요(모양만 보여요) |
| `.json` · `.xml` | **원문 / 트리** — 접고 펼치는 트리. 주석·끝 쉼표가 있는 JSON 도 읽고, 깨진 곳은 위치를 알려 줘요 |

- 미리보기는 **인쇄될 모양**을 보는 자리라 바탕이 늘 흰 종이예요. 고치려면 원문으로 돌아가요.
- 고른 모양(원문·표·미리보기)은 **Studio 전체에 기억**돼요. 다음에 여는 파일도 그 모양으로 열려요(못 쓰는 파일은 기본 모양으로).
- AI 기록 파일(`.atlas/private/agent/` 아래 `llm-call-tracker/` · `usage/` · `chats/`)은 기본이 표예요. **LLM 호출 추적**은
  이벤트마다 요약·토큰 열이 붙어 타임라인처럼 읽혀요(atlas-agent 설정의 `options.tracker.enabled` 를 켜야 기록돼요).

## 4. 탐색기 · 편집기 · 찾기

### 탐색기 트리

- **폴더는 화살표(›/⌄)**, 파일은 종류별 아이콘·색으로 보여요(테스트 파일은 비커 모양). 같은 아이콘이 탭·검색 결과·Ctrl+P 에도 쓰여요.
- 아래로 내려가면 **지금 보고 있는 곳의 상위 폴더들이 트리 맨 위에 붙어** 있어요. 누르면 그 폴더로, 파일을 그 줄에 떨어뜨리면 그 폴더로 옮겨요.
- 파일이 아주 많은 폴더는 1000개까지 먼저 그리고 "남은 n개 모두 보기" 한 줄을 붙여요.
- **트리 위 아이콘 5개**: 새 파일 · 새 폴더 · 새로 고침 · 모두 접기 · 사이드바 접기.
  새 파일·폴더는 **마지막으로 고른 자리**(폴더면 그 안, 파일이면 그 폴더) 기준으로 만들어요. `src/util.ts` 처럼 중간 폴더까지 한 번에 쓸 수 있어요.
  빈 곳을 누르거나 Esc 로 선택을 풀면 루트 기준이에요.
- 사이드바를 접으면 남는 **얇은 띠의 ›** 로 다시 펼쳐요(찾기·Run & Debug 사이드바도 같아요).

| 트리 조작 | 키 / 방법 |
|---|---|
| 이동 · 펼치기 · 접기 | ↑↓ · → · ← |
| 열기 · 이름 바꾸기 · 삭제(휴지통) · 전체 선택 | Enter · F2 · Delete · Ctrl+A |
| 복사 · 잘라내기 · 붙여넣기 | Ctrl+C · Ctrl+X · Ctrl+V (여러 개 가능, 같은 이름이면 `이름 copy`) |
| 되돌리기 · 다시 하기 | Ctrl+Z · Ctrl+Y (또는 Ctrl+Shift+Z) — 최근 50개 파일 조작. 삭제도 휴지통에서 되살려요 |
| 옮기기 | 폴더 위로 끌어다 놓기 |

- 트리의 복사·붙여넣기는 **Studio 안에서만** 동작해요. 경로 글자가 필요하면 우클릭 › **경로 복사**.
- Ctrl+Z 는 **트리에 포커스가 있을 때만** 파일 조작을 되돌려요. 편집기 안에서는 글자 편집을 되돌려요.

### 편집기

- **밖에서 바뀌면 바로 반영**돼요. AI 나 git 이 열어 둔 파일을 고치면 편집기도 곧바로 갱신돼요("⟳ 외부 변경을 반영했습니다").
  단, **저장 안 한 편집이 있으면 덮지 않고 알리기만** 해요. 그대로 저장하면 밖의 변경을 덮어쓰게 되니 판단해서 저장하세요.
- **정의로 이동**: 심볼을 **Ctrl+클릭**. 언어 서버가 있어야 동작해요(§12 언어 서버).
- **탭**: 끌어서 순서 바꾸기, 다음에 열 때 그대로 복원(최근 20개). 탭 바 오른쪽 아이콘으로 **편집 중인 탭만 남기기 · 저장된 탭 닫기 · 모두 닫기**.
- **저장 안 한 편집은 잃지 않아요.** 탭이나 창을 닫거나 다른 프로젝트를 열 때 탭마다 저장 / 저장 안 함 / 취소를 물어요.
- 탭 바 오른쪽: **모두 저장 · 자동 저장**(타이핑이 멈추면 잠시 뒤 저장) **· 분할**(오른쪽에 편집 창 하나 더).
- **cp949(EUC-KR) 같은 옛 인코딩**도 알아서 읽고, **저장할 때 그 인코딩 그대로** 써요. 편집기 오른쪽 위에서 인코딩을 바꿔 저장할 수도 있어요.
- 이미지(png·jpg·gif·webp·bmp·ico·avif)는 미리보기로 열려요. 2MB 가 넘는 텍스트는 앞부분만 읽기 전용으로 보여요.

### 타임라인 (파일 버전)

탐색기 아래 **타임라인** 섹션에 지금 파일의 저장 버전이 나와요. 행을 누르면 **그 버전 ↔ 지금 내용 비교**가 열리고,
**이 버전 복원**으로 되돌릴 수 있어요(저장해야 파일에 반영). 섹션 위 경계를 끌어 높이를 조절해요.

### 찾기

ripgrep 기반의 빠른 전체 검색 + 일괄 치환이에요.

- 검색창 오른쪽 토글: **대소문자 구분 · 단어 단위 · 정규식 · 작업 폴더(.atlas) 제외**(기본 켬).
- 결과 위에 **[파일 이름]** 섹션이 붙어서 이름이 맞는 파일도 함께 보여요.
- 오래 걸리면 **⏹ 중단**. 받은 결과는 남아요.
- 결과 행 **우클릭 → 이 파일 / 폴더 / 확장자 제외**(또는 이 폴더만 검색).
- **[포함/제외 조건]** 버튼: 조건을 모아 켜고 끄고 지우는 창. `node_modules/**` · `*.md` · `docs/` 처럼 직접 추가도 돼요.
- 치환도 **검색과 똑같은 조건**으로 돌아요. 결과에 안 보인 파일은 바뀌지 않아요.

## 5. Activity 화면 — 단계와 작업

아이콘 바의 **Activity** 가 프로젝트 진행의 중심 화면이에요.

### 단계(Stage) 탭

- 단계가 하나도 없으면 **'Activity 구성' 시작 페이지**가 보여요. [stage 추가]로 직접 만들거나, 챗에 "작업 파이프라인을 설계해 줘"라고 해요.
- 단계마다 탭 하나. 위에 목표, 아래에 **작업 목록**이 있어요. 오른쪽 책갈피의 **Flow** 탭으로 실행 흐름을 그려요.
- 탭은 끌어서 순서를 바꿔요. 탭의 ✕ 는 **숨기기**(폴더·결과는 남김) 또는 **완전 삭제**(되돌릴 수 없음) 중에 골라요.

### 작업(Activity) 목록

한 줄이 작업 하나예요. 열: **보기·편집 · ID · 이름 · 설명 · 실행 방식 · 결과 형식 · 마지막 실행**.

| 하고 싶은 일 | 방법 |
|---|---|
| 상세 보기 | 줄 맨 앞 **👁** — 오른쪽에 상세가 열려요(패널 위 **›** 로 접기). 줄을 클릭하면 선택만 돼요 |
| 편집 | **✎**, 더블클릭, 또는 ↑↓ 로 고르고 Enter |
| 순서 바꾸기 | 줄 왼쪽 **⣿ 손잡이**를 끌거나 **Alt+↑/↓**. 순서는 정의 파일에 저장돼서 팀이 같은 순서를 봐요 (정렬·필터 중엔 못 바꿔요) |
| 마지막 실행 확인 | 맨 오른쪽 칸: ✓ 성공 · ✗ 실패 · ⏸ 선행 대기 · ○ 실행한 적 없음 |
| 숨기기 | 상세의 **비활성** 체크 (목록의 "비활성 보기"로 다시 보기) |

상세는 세 칸이에요 — 위 **제목**(이름, 비활성, 🗑 삭제), 가운데 **내용**(정의·실행 설정·입력 폼·선행 조건·마지막 실행·파일),
아래 **실행 칸**(**▶ 실행 · ✎ 편집 · ☑ 실행버튼 보이기 · 📂 결과**). 내용이 길어도 제목과 실행 버튼은 제자리에 있어요.

### 작업 종류

종류(실행 방식)는 **등록할 때 정하고 바꿀 수 없어요.** 다른 방식이 필요하면 새로 만드세요.

| 종류 | 동작 |
|---|---|
| **Skill 구성** | AI 가 절차서(skill.md)를 수행해요 — 챗의 한 턴으로 실행 |
| **Run (터미널)** | 명령을 통합 터미널에서 실행 |
| **Debug 실행** | 실행 구성(launch config)으로 디버거 실행 |
| **Tool call** | 등록된 툴 실행 |
| **Flow** | 여러 작업을 흐름대로 실행 |

### 실행하기

- **▶ 실행** — 입력 폼이 있으면 **폼이 먼저 떠요.** 필수 값이 비면 실행되지 않아요.
- **챗에서 실행** — **☑ 실행버튼 보이기**를 켜 두면 챗 입력창에 **`/`** 를 쳤을 때 목록에 떠요(§6).
- **결과** — **📂 결과**가 결과 폴더의 최신 파일을 열어요.
- **선행 조건** — 앞 작업이 끝나지 않았으면 실행이 막히고 상세에 '선행 대기'가 보여요.
  걸거나 풀기: `atlas activity set-requires <id> --requires '[{"activity":"앞선-id"}]'` (`'[]'` 는 해제)

### 입력 폼

대상(화면 코드·주차 등)을 받아 실행하는 작업은 입력 폼을 선언해요.

- 편집 화면(✎)의 **"입력 스키마" 카드**에서 선언해요(형식은 표준 JSON Schema).
- **Tool call** 종류는 선언하지 않아도 그 툴의 파라미터가 자동으로 폼이 돼요.
- 어디서 실행하든(▶ · 챗 `/` · `atlas activity run <id> -p 키=값`) **같은 폼, 같은 검사**를 써요.

### 편집 화면

- 왼쪽 구조 트리 + 오른쪽 카드에서 고치고, 확정하면 바로 저장돼요. **저장 버튼은 맨 위 제목 줄**에 있어요.
- 위쪽 **"원문" 토글은 읽기 전용**이에요. 고치는 곳을 한 군데로 모아 둔 거예요.
- 정의는 `.atlas/workbenches/<워크벤치>/stages/<단계>/activities/<id>/` 폴더 하나에 있어요 — `activity.json`(정의) + `skill.md`(절차서) + 딸린 파일.
  예전 배치를 쓰던 프로젝트는 `atlas activity migrate` 로 정리해요.

### 내장 작업

만들지 않아도 늘 있는 작업이에요(`atlas activity list` 에서 "[내장]").

| 작업 | 하는 일 |
|---|---|
| **가이드 물어보기** (`guide-ask`) | Studio 사용법 질문에 맞는 가이드를 찾아 근거와 함께 답해요. 챗 `/` 나 `atlas guide <질문>` |
| **소스 매뉴얼화** (`source-manualize`) | 폴더·모듈·화면·기능 하나를 지정하면 AI 가 읽고 개요·용어·구조·사용법·설정·주의점 문서를 `.atlas/wiki/manual-<이름>.md` 로 만들어요. 독자(개발자/사용자/AI)를 고르고, 기존 문서는 고치지 않고 **갱신 제안**만 남겨요 |

같은 id 로 프로젝트 작업을 만들면 그쪽이 우선해요.

### Flow 탭 — 실행 흐름 그리기

단계 화면 오른쪽 **Flow** 탭에서 "어떤 작업을 어떤 순서로" 할지 그려요. 여긴 **정의**를 그리는 곳이고, 실행 결과는 **실행 기록** 화면에서 봐요.

> ⚠️ 그래프 편집기(§9)와는 달라요 — Flow 는 *일의 순서*, 그래프 편집기는 *데이터 계산 파이프라인*이에요.
> AI 에게 "그래프를 만들어 줘"라고 할 땐 어느 쪽인지 말해 주세요.

- **노드 만들기**: 왼쪽 **팔레트**에서 작업을 캔버스로 끌어다 놓아요(더블클릭도 돼요). 이미 쓴 작업은 '사용 중'으로 표시돼요.
  flow 를 먼저 고르거나 **＋ flow** 로 만들어야 놓을 자리가 생겨요.
- **범위**: 팔레트 위 **이 stage / 전체** — 전체로 바꾸면 **여러 단계를 잇는 흐름**도 그릴 수 있어요.
- **흐름 먼저, 작업은 나중에**: **＋ 빈 노드**를 놓으면 아직 작업이 없는 보라색 점선 노드가 생겨요. 이름만 붙여 두고 나중에
  속성 창에서 **[이 id 로 activity 만들기]** 나 **[기존 activity 로 연결]**. 빈 노드가 있으면 저장은 되지만 실행은 안 돼요.
- **연결선**: 툴바의 엣지 모드(→ 실행 순서 · ✗ 실패 시 분기 · ↻ 되돌아가기)를 고르고 노드에서 노드로 끌어요.
  자기 자신으로 끌면 자기 재시도예요. 우클릭으로 종류·최대 재시도 횟수를 바꿔요.
- **속성 창**: 연결선 = 종류와 **설명**(AI 가 읽는 실행 안내에 그대로 실려요 — "왜 이 순서인지, 무엇을 넘겨받는지"),
  노드 = 실패 시 처리(**중단 / 건너뜀 / 사람 개입**)와 재시도 횟수.
- **⏱** 은 흐름 전체의 시간 예산(분)이에요.
- **편집은 초안**이라 저장하기 전엔 파일에 닿지 않아요. 단계를 옮겨도 저장 안 한 편집은 되살아나요. **되돌리기**는 노드 위치까지 되돌려요.

### 반복과 분기 — "될 때까지"

사람이 붙지 않는 실행(명령 실행, flow 노드, 서브에이전트)은 한 번 돌고 끝나요. "될 때까지"가 필요하면
**검증 작업을 flow 노드로 두고 되돌아가는 연결을 이어요.** 검증이 실패할 때마다 구현 노드가 **새 세션**으로 다시 돌고,
검증 결과가 다음 시도에 함께 전달돼요(최대 횟수까지).

- **성공 판정**: Skill 구성 노드는 결과 파일을 써야 성공이에요. 결과 형식이 json 이면 절차서 `## 산출물` 의 JSON Schema 로 검사하고,
  결과 문서에 `verdict: fail` 이 있으면 실패로 봐요 — 검토 작업은 이 형식으로 판정을 남기면 돼요.
- 검토 작업이 결과를 고치지 못하게 하려면 쓸 수 있는 도구를 좁혀요(`allowedTools`, 예 `["Read","Grep","Glob"]`).
  지금은 **Claude Code 백엔드에서만** 지켜져요(atlas-agent 백엔드는 아직 이 제한을 걸지 못해요).
- 선택 단계는 노드의 `when` 조건으로, 실행 파라미터를 보고 건너뛰게 할 수 있어요.
- 노드별 회차·결과는 실행 기록 화면이나 `atlas activity jobs` 로 봐요(⚠ = 사람 개입 필요).
- 챗에서 직접 실행하는 턴에는 적용되지 않아요. 거기선 사람이 이어 가요.

### 격리 실행 (git worktree)

코드를 고치는 flow 는 정의에 `"isolation":"worktree"` 를 두면 실행마다 별도 작업 공간(브랜치 `atlas/run/<flow>/<시각>`)에서 돌아요.
`"merge":true` 면 성공 시 현재 브랜치에 합치고 정리해요. 충돌이면 "사람 개입 필요"로 끝나고 작업 공간이 남아요.
커밋 안 한 변경은 들어가지 않으니 먼저 커밋해 두세요.

### 템플릿으로 내보내기

워크벤치가 충분히 다듬어졌으면 다른 프로젝트에서 쓸 수 있게 꺼내요. 챗에 "이 워크벤치를 템플릿으로 내보내 줘"라고 하면
**Workbench Builder** 가 프로젝트 고유 내용(실행 이력·결과물)을 빼고 일반화해 줘요. 명령으로는
`atlas workbench export` → `validate` → `pack`(zip) → `install`(이 PC 에 등록) 순서예요. zip 을 팀원에게 주면
각자 **[워크벤치 템플릿 등록 (zip)…]** 으로 등록해 써요.

### 스킬 내보내기

`atlas skill export <작업 id>` 는 절차서를 표준 **SKILL.md**(`.atlas/skills/`)로 내보내요. atlas-agent 가 이름으로 찾아 수행하는 형식이에요.
flow 를 내보내면 실행 계획서(부모) + 하위 스킬 묶음이 돼요. 원본을 고친 뒤엔 `atlas skill check` 로 낡은 스킬을 찾아 다시 내보내요.

## 6. 챗 — AI 와 대화하기

챗은 어느 화면에서나 쓸 수 있고, 화면을 옮겨도 **쓰던 대화가 이어져요.**

### 기본

- **누구와 대화하나**: 대화를 연 화면에 따라 AI 역할이 정해져요 — 일반 화면은 Atlas Agent, 단계 탭은 Stage Agent,
  툴 패널은 Tool Builder, 그래프 화면은 Graph Agent 등([용어집](glossary.md#4-ai-와-지식)). 매 메시지마다 **지금 화면 상태**가 함께 전달돼요.
- **AI 가 할 수 있는 일**: 파일 읽기·쓰기, `atlas` 명령 실행, Studio 화면 확인·파일 열기·새로 고침, 메모리 저장,
  폼·화면 툴 띄우기(챗 카드나 팝업으로).
- **대화 탭바**: 맨 위 한 줄 — 열린 대화 탭과 **＋**(새 대화), 오른쪽에 **🕘 이력**과 **도킹 위치**.
- **도는 중인 대화는 끊기지 않아요.** 새 대화를 열거나 이력을 봐도 계속 진행돼요(● 표시). 멈추려면 입력 바의 **■** 나 탭의 ✕.

### 입력 바

| 버튼 | 하는 일 |
|---|---|
| 📎 / **Ctrl+V** | 파일 첨부. 화면 캡처를 복사해 붙여넣으면 `.atlas/uploads/` 에 저장되고 썸네일 칩으로 붙어요 |
| **`/`** · ⚡ | 작업 목록을 열어 바로 실행 (아래) |
| 📄 | **이 대화에서 AI 가 고친 파일** 목록 — 누르면 편집기로, 🕘 은 변경 이력으로 |
| 모델 선택 | 고르면 **하던 대화도 다음 응답부터** 그 모델로 (Claude Code 백엔드일 때) |
| 권한 모드 | **기본 / 편집 허용 / 계획** (atlas-agent 백엔드일 때, 아래) |
| ■ | 지금 응답 멈추기 — 그 대화가 띄운 서브에이전트·자식 프로세스까지 함께 멈춰요 |

### `/` 로 작업 실행

- 입력창에 **`/`** 를 치면 실행버튼을 켜 둔 작업 목록이 떠요. 타이핑으로 좁히고 ↑↓, Enter 로 실행해요(Esc 닫기).
- 고른 작업은 **이 대화의 턴으로** 실행되고, 입력 폼이 있으면 먼저 물어봐요.
- 목록에 올리기: 작업 상세의 **☑ 실행버튼 보이기** (CLI `atlas activity chat-action <id> on`).
- **atlas-agent 백엔드**에서는 프로젝트 스킬(`.atlas/skills/` 중 사람이 부를 수 있는 것)도 함께 떠요. 고르면 입력창이 `/이름 ` 으로 채워져요.
- 응답 중에는 실행할 수 없어요(턴이 끝난 뒤 골라요).

### 권한 승인

- AI 가 도구를 쓰려고 할 때 승인이 필요하면 챗 안에 **승인 카드**가 와요. 선택 질문도 카드로 와요.
- atlas-agent 백엔드의 카드는 **왜 묻는지**(걸린 규칙)와 명령·경로를 보여 주고, **항상 허용**을 세 범위로 고를 수 있어요:
  이 대화 동안 / 이 PC(`.atlas/private/agent/permission.json`) / 프로젝트(`.atlas/permission.json` — 팀 공유).
- **권한 모드**(atlas-agent): **기본**(위험한 명령·프로젝트 밖 쓰기만 물어요) · **편집 허용**(프로젝트 안 삭제도 묻지 않아요) ·
  **계획**(읽기만 하며 계획을 세워 보여 주고, **계획 승인**을 누르면 실행). 다음 메시지부터 적용돼요.

### 응답 보기

- 응답 아래 아이콘: **MD 원문 복사 · 텍스트 복사**. 드래그로 일부를 고르면 그 아래에도 같은 아이콘이 떠요.
- 복사 아이콘 왼쪽에 **걸린 시간**이 보여요(예: `14:03:21 ~ 14:05:02 · 1m 41s`).
- 응답 속 **웹 주소**는 기본 브라우저로, **프로젝트 파일 경로**(`src/App.tsx#L42`)는 편집기의 그 줄로 열려요.
- 응답이 나오는 동안 자동으로 맨 아래를 따라가요. 위로 올려 읽는 동안엔 멈추고, 다시 내리면 또 따라가요.

### 서브에이전트

항목이 많은 반복 작업은 AI 가 항목마다 **별도 세션(서브에이전트)** 에 맡길 수 있어요.

- 대화에 접힌 블록 **`▸ 서브에이전트 · <이름>`** 이 붙고, 진행 상태(⋯ / ✓ / ✗)와 마지막 줄이 보여요. 누르면 무엇을 했는지 펼쳐져요.
- 이 내용은 **화면에만** 남고 AI 에게는 요약만 가요. 그래서 긴 배치에서도 대화 품질이 유지돼요.
- 보고는 `.atlas/private/agent/scratch/subagents/` 에 남아요.

### 대화 이력

**🕘** 를 누르면 프로젝트의 지난 대화 전체가 최근순으로 보여요(다른 화면에서 연 대화도). 고르면 새 탭으로 열려요.
지난 대화의 화면 상태 정보는 **접힌 카드**로 보여서 실제 대화만 읽혀요. 프로젝트 폴더를 옮겨도 이력은 복원돼요.

### AI 에게 무엇을 기억시키나

| 말하는 방법 | 어디에 남나 | 언제 쓰이나 |
|---|---|---|
| "이건 앞으로 항상 이렇게 해 줘" | **지시서** `.atlas/AGENT.md` | 모든 대화의 시스템 프롬프트 |
| "이거 기억해 둬" | **메모리** `.atlas/memory/` (나만: `.atlas/private/memory/`) | 다음 대화에 자동으로 |
| "가이드로 남겨 줘" | **가이드** `<워크벤치>/guides/` | AI 가 필요할 때 `atlas guide` 로 찾아 읽어요 |
| "위키에 정리해 줘" | **위키** `.atlas/wiki/` | `atlas wiki grep` 으로 검색 |
| "내 노트에 적어 둬" | **개인 노트** `~/.atlas/notes/` | 요청할 때만 |

### 백엔드와 계정

- 기본은 **Claude Code**. **설정 ⚙ › 환경 설정 › 에이전트**에서 **atlas-agent** 로 바꿀 수 있어요(설치·실행 자동).
- atlas-agent 로 바꾸면 입력 바의 모델 선택이 사라져요 — 모델은 atlas-agent 설정 파일이 정하기 때문이에요.
- Claude 로그인이 풀리면 챗에 **"⚠ Claude 인증이 만료됐습니다"** 카드가 떠요. **[터미널에서 로그인]** 후 메시지를 다시 보내면 이어져요.
- 턴이 실패하면 안내 아래 **백엔드 진단 N줄**을 펼쳐 원래 오류를 볼 수 있어요. 하단 **문제**·**로그** 탭에도 남아요.

### Studio 개선 랩

AI 에게 화면·기능 테스트를 시키면 시나리오를 만들어 실행하고 결과를 `~/.atlas/lab` 에 남겨요. 쓰다가 불편하거나 이상한 점을 말하면
그것도 피드백으로 기록돼요(`atlas lab list`). 제품 개선에 쓰여요.

## 7. 작업 목록 · 실행 기록 · 변경 이력

### 작업 목록 — 체크하고 [실행]

아이콘 바의 **작업 목록**은 이 프로젝트가 처리할 **대상**의 목록이에요(화면·문서·CR·할 일…).
항목은 **＋** 로 직접 넣거나, 챗에 "작업 목록을 구성해 줘"라고 하면 AI 가 프로젝트의 파일·툴에서 목록을 연결해 줘요.

```
 ☑    완료  사용  작업 항목        상태     진척  태그     관리
 ☑    ☐    ☑    SCR-1 화면1     doing    1/3  tierA  [📋 🗑]   ← 📋 = 이 항목에 걸린 작업들
 ☑    ☐    ☑    SCR-2 화면2     todo     0/3  tierB  [📋 🗑]
 ·    ☐    ☐    SCR-9 화면9     disabled  –   tierB  [📋 🗑]   ← 사용 끔 — 흐리고 고를 수 없어요
                                    ↑ 체크한 뒤 위의 [실행] 또는 [삭제]
```

- **선택은 체크박스로만** 해요. 머리글의 ☑ 는 보이는 행 전체(필터가 걸려 있으면 걸러진 행만)를 골라요.
- **값은 표에서 바로 고쳐요** — 셀 더블클릭(또는 ✎). 제목·태그·사용자 정의 속성을 고칠 수 있고, 항목 id 는 못 고쳐요.
  직접 넣은 목록에서만 돼요(파일·툴에서 가져온 목록은 원천을 고치세요).
- **사용 열**: 끄면 이번엔 하지 않을 항목이 돼요. 지우지 않고 치워 두는 자리예요.
- **[삭제]**: 체크한 항목을 지워요(만든 결과물은 남아요). 직접 넣은 목록에서만 보여요.
- **열 설정 ⚙**: 위쪽은 기본 열 보이기(이 PC), 아래 **[사용자 정의 열]** 은 항목 속성(tier·owner 등)을 열로 추가 — **팀이 함께 봐요.**

**[실행] 을 누르면** 목록 자리가 **실행 화면**으로 바뀌어요(**← 뒤로**로 돌아와요).

| 실행 화면에서 | 내용 |
|---|---|
| 왼쪽 | **작업 지시서** 목록. 맨 위 **＋** 가 새로 쓰기 |
| 오른쪽 | 고른 지시서의 상세 — 이름, 연결할 **작업(또는 flow)**, 실행 방식, **지시문서** |
| **[선택 N건 실행]** | 고른 대상에 이 지시서를 걸고 하나씩 수행 |
| [저장만] | 실행하지 않고 저장 (고른 대상엔 걸려요) |
| 🗑 | 지시서 지우기 (확인을 한 번 물어요, 실행 기록은 남아요) |

**실행 방식은 연결한 작업이 정해요.**

| 연결한 것 | 실행 방식 |
|---|---|
| 툴 · 코드 · 터미널 작업 | **헤드리스 잡** — 사람 없이 실행하고 ✓/✗ 기록. 통합 터미널에 탭이 열려 진행이 보여요(멈추려면 Ctrl+C). 하나가 실패해도 다음으로 가요 |
| AI 작업 · flow · 연결 안 함 | **챗 위임** — 대상마다 안내 문서를 만들어 AI 대화로 진행. 사람이 보는 앞에서 진행되고, 결과는 산출물과 완료 체크로 확인해요. **지시문서는 이쪽에서만** 써요 |

- 처음엔 지시서가 하나도 없어요. 대상을 체크하고 [실행] → **＋** 로 첫 지시서를 쓰면, 저장하는 순간 고른 대상에 걸려요.
- 항목 하나만 다루려면 관리 열의 **📋** — 그 항목에 걸린 작업별로 실행·완료 체크·연결 해제를 해요.
- 걸린 전부를 한꺼번에 돌리는 배치는 명령으로: `atlas tasks run <지시서 id> --all`
- 예전 방식의 공통·항목 지시서가 남아 있으면 실행 화면 위에 **[이전하기]** 안내가 떠요.

### 실행 기록 — 무엇이 언제 돌았나

**실행 기록** 화면(아이콘 바 우클릭으로 켜기)은 실행 한 번마다 남는 기록(`.atlas/jobs/`)을 보여 줘요.

- 왼쪽 목록 표시: ✓ 성공 · ✗ 실패 · ⚠ 사람 개입 필요 · … 진행 중 · ⏹ 사용자 중지 · → 챗에 위임
- 오른쪽 상세: 작업 실행은 대상·실행 방식·안내 문서, flow 실행은 **노드별 회차·상태·결과**, AI 실행은 결과와 **실패 이유**
  (결과 파일 없음 · 형식 위반 · 검토 판정), 거부된 도구, 요약.
- 결과 파일·대화 기록·원본 기록은 버튼으로 편집기에서 열어요. CLI: `atlas activity jobs`

### 변경 이력 — 파일 버전 타임라인

**변경 이력** 화면(아이콘 바 우클릭으로 켜기)은 프로젝트 파일이 **저장될 때마다** 남는 버전을 보여 줘요 — 사람이 고쳤든, AI 가 고쳤든, 다른 프로그램이 고쳤든.

- AI 가 고친 버전에는 도구 배지(Edit/Write 등)와 어느 대화에서 고쳤는지가 붙어요.
- 버전을 고르면 **직전 버전과 비교**가 나란히 보여요. "파일 열기"로 편집기로 가요.
- 목록은 최신 N개(50/100/200/500)까지 보이고, 나머지는 **시간대·일·월 막대 통계**로 보여요. 내리면 계속 이어 붙고, 막대를 누르면 그 구간만 봐요.
- 범위: 전체 / 오늘 / 7일 / 30일, 또는 시작~끝을 분 단위로.
- 보존: 파일당 최근 50개·30일. 삭제·1MB 넘는 파일·바이너리는 "바뀌었다"는 사실만 남아요.
- CLI: `atlas file-history [--file <경로>] [--from 2026-10-01] [--to "2026-10-01 18:00"]`

## 8. Run & Debug 와 하단 패널

### 실행 구성

- 기준 파일은 **`.atlas/launch.yaml`** 이에요(없으면 "기본 템플릿 생성" 버튼). **`.vscode/launch.json` 도 자동으로 읽어요**(이름이 겹치면 " (vscode)").
- `${workspaceFolder}` 를 쓸 수 있고, `console: integratedTerminal` 이면 통합 터미널에서 실행돼요.

### 실행과 조작

| 키 | 동작 |
|---|---|
| **F5** | 시작 / 멈춰 있으면 계속 (이미 실행 중이면 반응 없음) |
| **Shift+F5** · **Ctrl+Shift+F5** | 중지 · 재시작 |
| **F6** | 일시정지 |
| **F10 / F11 / Shift+F11** | 한 단계 넘기기 / 안으로 / 밖으로 |

- **여러 세션 동시에**: 사이드바의 **▶** 로 다른 구성을 추가로 띄워요(예: 서버 + 화면 동시 디버그). F5 는 중복 실행을 막아요.
- **중단점**: 편집기 줄 번호 옆을 클릭. 중단점 목록의 ✏ 로 **조건식**(참일 때만 멈춤)을 넣어요.

### 디버그 어댑터

| 언어 | 준비 |

### 하단 패널 (Ctrl+`)

| 탭 | 내용 |

| **디버그 콘솔** | 디버그·그래프 실행의 출력 + 식 계산 |
| **문제** | 실패 목록(대화 턴 실패, 그래프 제출 실패 등) — 눌러서 상세 확인 |

터미널 복사·붙여넣기는 [단축키](shortcuts.md#5-통합-터미널) 를 보세요. 터미널에 포커스가 있을 때 `Ctrl+R` 은 셸의 명령 검색으로 가요.

## 9. 그래프 편집기

아이콘 바의 **그래프** 아이콘(우클릭으로 켜기). [atlas-engine](../engine/README.md) 으로 **데이터 처리 파이프라인**을 그리고, 돌리고, 디버그해요.
그래프 파일은 `.atlas/graphs/<id>.json` 이에요.

- **엔진 준비**: 실행하면 내 PC 의 엔진에 자동으로 붙고, 꺼져 있으면 켜요. 설치는 설정 ⚙ › 환경 설정 › 구성 요소 › **그래프 엔진** 카드(또는 `atlas engine install`).
- **노드 클래스**: 그래프 목록의 **"새 노드 클래스"** — Python 소스(`.atlas/graphs/src/…`)와 카탈로그가 만들어져요. 노드의 **"코드"** 버튼으로 소스를 고치면 다음 실행에 바로 반영돼요.
- **Python 환경**: pandas 같은 패키지가 필요하면 그래프 목록 아래 **"Python 환경"** 에서 환경을 만들고(`requirements.txt`) **준비** 를 눌러요.
  노드 클래스에 환경을 연결하면 그 종류의 노드는 모두 그 환경으로 돌아요. requirements 를 고치면 "재준비 필요"가 뜨니 다시 **준비**.
  노드 속성(⚙)의 **실행 환경** 탭, 그래프 정보의 **Python 환경 (일괄 지정)** 으로 바꿔요. CLI: `atlas graph env …`
- **팔레트**: 왼쪽 서랍에서 노드 클래스와 **다른 그래프**(놓으면 서브그래프로 들어가요)를 끌어다 놓아요.
- **실행**: 툴바 **▶**. 진행은 디버그 콘솔에, 노드 상태는 캔버스 색으로 보여요. 중단점(그래프에 저장)에서 멈춰요. 화면 없이: `atlas graph run <파일>`
- **노드 소스 디버그**: 툴바 **🐞** — 중단점을 건 노드의 Python 소스를 한 줄씩 디버그해요. 끝내려면 🐞 를 다시 눌러요.
  노드 우클릭 **"재현 디버그"** 는 지난 실행에서 받은 입력으로 그 노드만 다시 돌려요.
- **AI 와 함께**: 그래프 화면의 챗은 **Graph Agent** 예요. 그래프 구성·노드 만들기·실행 오류 진단을 도와줘요.
- **엔진을 AI 에게 직접 쥐여 주기**: 엔진을 설치하면 엔진 MCP 서버가 `atlas-engine` 이라는 이름으로 **꺼진 채** 등록돼요.
  툴 패널의 MCP 섹션에서 켜면(또는 `atlas mcp enable atlas-engine`) 새 대화부터 AI 가 그래프를 직접 실행하고 노드를 검색해요.
  도구 목록은 모든 대화의 비용이라 필요한 프로젝트에서만 켜는 걸 권해요.

## 10. 툴 패널 · MCP

### 툴 (🛠)

AI 가 부르는 프로젝트 도구(`tools/*.yaml|json`)를 관리해요.

| 종류 | 뜻 |
|---|---|
| `code` | 프로그램(코드)으로 일하는 도구 |
| `form` | 사용자에게 폼을 띄워 답을 받아 AI 에게 돌려줘요 — **코드 없이 선언만으로** |
| `render` | 표·차트·문서·버튼 같은 화면을 챗 카드나 팝업으로 보여 줘요 — **코드 없이 선언만으로** |

- 만들 땐 툴 패널에서 **Tool Builder** 챗을 열어 말로 부탁하는 게 기본이에요. 예: "보고 대상 주를 고르는 폼 도구를 만들어 줘".
- form·render 는 미리보기를 볼 수 있어요.

### 외부 패키지

`code` 툴은 Studio 에 들어 있는 Node 로 돌아서 **파일 읽기·쓰기, HTTP 호출 같은 기본 기능은 설정 없이 바로** 써요.
npm 패키지(예: DB 드라이버)가 필요할 때만 툴 폴더에 `package.json` 을 두면 돼요.

- **설치는 Studio 가 알아서 해요** — 툴을 실행할 때 없으면 설치하고 이어서 실행해요. 이 섹션은 상태를 보고 원하면 **미리 설치**하는 곳이에요.
- 배지: **준비됨** / **미설치** / **재설치 필요** — 셋 다 할 일은 없어요(자동).
- 패키지는 **툴마다 따로** 설치돼서 서로 다른 버전을 써도 부딪히지 않아요.
- 설치 중 컴파일이 필요한 패키지(네이티브 모듈)는 못 써요. 순수 JavaScript 패키지를 고르세요.

### MCP 서버

외부 도구 서버를 연결해요. 형식은 Claude Code 의 `.mcp.json` 과 같아요.

- 툴 패널의 **MCP 서버** 섹션에서 등록(스펙 JSON 붙여넣기)·수정·**켜기/끄기**·삭제해요. 새 대화부터 적용돼요.
- 두 자리에 등록할 수 있어요: **이 PC 전체**(`~/.atlas/mcp.json`)와 **이 프로젝트**(`.atlas/mcp.json`). 같은 이름이면 프로젝트가 이겨요.
- CLI: `atlas mcp list|add|remove|enable|disable` (`-g` = 이 PC 전체)

## 11. 개인 노트

아이콘 바의 **개인 노트** — **프로젝트와 상관없는 나만의 지식 공간**이에요. 어느 프로젝트를 열어도 같은 노트가 보여요.

- 저장 위치는 **`~/.atlas/notes` 의 평범한 마크다운 파일**이에요. 이 폴더를 **Obsidian** 에서 그대로 열 수 있고, git 이나 클라우드 동기화 폴더로 써도 돼요.
- 목록은 **수정일로 묶여 최신순**이에요. 마우스를 올리면 생성·수정 시각이 보여요.
- **연결**: 본문에 `[[다른 노트 제목]]` 을 쓰면 이어져요. 아래에 링크·백링크가 보이고, 없는 노트 링크를 누르면 그 제목으로 새로 만들어요.
  `[[` 를 치면 노트 제목, `#` 을 치면 태그가 자동완성돼요.
- **미리보기(👁)**: `[[링크]]` 클릭 이동, `![[다른 노트]]` 는 그 노트를 카드로 끼워 넣어요(`![[노트#섹션]]` 은 그 부분만).
- **데일리 노트(📅)**: 오늘 날짜 노트를 열거나 만들어요. "일단 여기 적고, 쓸 만한 건 정식 노트로" 쓰는 기본 수신함이에요.
- **그래프 보기**: 노트를 고르지 않은 기본 화면 — 노트(원)와 링크(선)의 지도예요.
- **내보내기 ⇪ / 가져오기 ⇩**: zip (가져오기는 있는 노트는 두고 새 것만 추가).
- **AI 와 함께**: "이 아이디어 노트에 적어 둬", "내 노트에서 ○○ 찾아 줘". AI 는 **요청할 때만** 노트를 봐요.
- 평범한 파일이라 비밀번호·API 키 보관은 권하지 않아요.
- CLI: `atlas notes list|grep|read|add|write|remove|daily|links|export|import`

## 12. 설정

아이콘 바 맨 아래 **⚙**. 값을 어떻게 바꾸고 안 될 때 무엇을 볼지는 도움말 창의 **가이드 › 설정**(`atlas guide settings`)에도 있어요.

| 탭 | 내용 |
|---|---|
| **프로젝트** | 프로젝트 정보, **워크벤치**(목록·전환·추가·템플릿 선택), **홈 화면**, **작업자**(결과물 작성자 표시) |
| **환경 설정** | 아래 4개 하위 탭 |
| **Atlas 개발자** | Atlas 소스 저장소 접근 권한이 있는 개발자에게만 보여요 |

**환경 설정 하위 탭**

| 하위 탭 | 내용 |
|---|---|
| **에이전트** | 백엔드(claude-code / atlas-agent) · **기본 모델** · **에이전트 프로파일** · 고른 백엔드의 설정(Claude 계정 관리 / atlas-agent 의 주소와 **Config**) |
| **일반** | 표시 언어 · 테마 · 글꼴 — 자동 저장 |
| **언어 서버** | 정의로 이동에 쓰는 언어별 서버 상태와 **[설치]** (TypeScript/JavaScript · Python · Rust · Java). 설치는 `~/.atlas/lsp` 에만 들어가 PC 의 다른 환경을 바꾸지 않아요 |
| **구성 요소** | 설치·업데이트 확인·실행을 모은 곳 — **그래프 엔진 · 에이전트 서버 · 디버그 어댑터 · 브라우저 연동** |

헤더의 ⟳ 는 전체 다시 읽기예요.

### 기본 모델

모델을 따로 고르지 않은 대화가 쓰는 모델이에요(챗 입력 바에서 고른 모델은 그 대화에만 적용).

- **Claude Code**: **[모델 목록 새로고침]** 을 누르면 설치된 Claude Code 에 직접 물어 목록을 받아 와요(이 PC 에 캐시).
  `opus` · `sonnet` · `haiku` 같은 **별칭**은 "그 계열의 최신"이라 새 모델이 나와도 따라가요. 고정하려면 정확한 모델 id 를 고르고,
  목록에 없으면 **직접 입력…**. CLI: `atlas models list [--refresh]`
- **atlas-agent**: 목록은 atlas-agent 설정 파일의 `llm_config.prefer_model_config` 에서 읽어요. 모델 id 는 `provider/name` 모양이에요
  (예: `anthropic/claude-haiku-4-5`).
  > ⚠️ 현재 atlas-agent 는 여기서 고른 모델이 실제로 적용되지 않을 수 있어요. 모델을 바꾸려면 **Config** 버튼으로 설정 파일의 `prefer_model_config` 를 고치세요.

### 에이전트 프로파일

"백엔드 + 모델" 조합에 이름을 붙여 두고, 작업마다 다른 AI 를 쓰게 할 수 있어요.

- 화면에서 추가하거나 `atlas agents add <이름> --backend atlas-agent --model <모델>`.
- 저장 위치: 프로젝트(`.atlas/agents.json`, 팀 공유) 또는 이 PC(`--machine` → `~/.atlas/agents.json`).
- 쓰는 곳: 작업 정의의 `agent` 항목, `atlas activity run <id> --agent <이름>`, `atlas subagent` · `atlas infer` 의 `--agent`.
- `atlas agents resolve <이름>` 으로 실제로 무엇으로 풀리는지 확인해요. API 키는 프로파일에 넣지 않아요.

### 구성 요소 카드

그래프 엔진과 에이전트 서버 카드는 모양이 같아요 — 상태 줄 + **[업데이트 확인]**(없으면 [설치]) + 시작/재시작.
설치 파일은 이 저장소의 Releases(`engine-v*`, `agent-v*`)에서 받아 `~/.atlas/engine`, `~/.atlas/atlas-agent` 에 설치돼요.

## 13. 언어 · 테마 · 글꼴

### 표시 언어

한국어(기본)·English. **설정 ⚙ › 환경 설정 › 일반 › 표시 언어**에서 고르면 **바로** 바뀌어요.

다른 언어를 더하거나 문구를 고치려면 언어 팩 파일 하나면 돼요(재설치 없음).

1. 설치 폴더의 `locales/en.json` 을 복사해요(전체 문구가 들어 있는 견본).
2. `locale`(언어 코드)과 `name`(목록에 보일 이름)을 바꾸고 `strings` 의 값을 번역해요. 키는 그대로 둬요.
3. `~/.atlas/locales/<코드>.json` 으로 저장해요.

번역 안 한 문구는 한국어로 보여서 일부만 번역해도 괜찮아요. `en.json` 처럼 내장 언어와 같은 이름으로 두면 내장 번역을 덮어써요.

### 테마와 글꼴

- **다크**(기본)·**라이트**. 바로 반영되고 이 PC 에 저장돼요. 편집기도 함께 바뀌어요(그래프 편집기는 다크 유지).
- **글꼴**: 분류별 크기·글꼴. 기본값은 VS Code 와 같아요.
- 브라우저 확장 패널은 자기 ⚙ 에 따로 라이트/다크가 있어요.

## 14. 브라우저 확장

Chrome·Edge 옆에 Studio 의 AI 챗을 붙여요. AI(**Atlas Bridge Agent**)가 지금 보는 웹 페이지를 읽고, 누르고, 입력하고,
네트워크·콘솔까지 보며 테스트·문제 진단·화면 명세 작성을 해요.

### 설치 (한 번만)

1. 설정 ⚙ › 환경 설정 › 구성 요소 › **브라우저 연동** — 확장 폴더(`~/.atlas/browser-extension`)를 준비해 줘요.
2. 브라우저의 확장 관리 페이지(`chrome://extensions`)에서 **개발자 모드**를 켜고 **"압축해제된 확장 프로그램 로드"** 로 그 폴더를 골라요.
   (브라우저 정책상 자동 설치가 안 돼서 한 번은 직접 해야 해요.)
3. 확장 패널에서 프로젝트와 **페어링**해요.

### 쓰는 법

- **패널은 두 곳 중 편한 곳에**: **사이드 패널**(툴바의 확장 아이콘 클릭 — 지금 탭을 다뤄요) 또는 **별도 창**(헤더 ↗, 또는 아이콘 우클릭 —
  마지막으로 본 탭을 따라가고, 탭 이름을 누르면 📌 고정). 한 번에 한 곳에만 열려요. 옮기면 대화도 따라가요.
- **대화는 연결할 때마다 새로** 시작해요. 지난 대화는 🕘 이력에서 이어 가요.
- 모델 선택, `/` 작업 실행, 캡처 붙여넣기, 응답 복사는 Studio 챗과 같아요.

### 패널의 탭 4개

| 탭 | 내용 |
|---|---|
| **대화** | AI 챗 |
| **관련 소스** | **수정 파일**(이 대화 / 이 화면에서 AI 가 고친 파일) + **관련 소스**(지금 화면을 이루는 소스 목록) |
| **탐색기** | 프로젝트 파일 트리 |
| **검색** | 프로젝트 전체 검색·치환 |

뒤의 세 탭은 **같은 편집기를 함께 써요** — 탭을 옮겨도 열어 둔 파일과 편집 내용이 남아요. 편집기·미리보기·타임라인·정의로 이동은 Studio 와 같아요.

**화면의 소스는 프로젝트에 쌓여요.** 대화 탭의 빠른 작업 **"관련 소스 찾기"** 를 누르면 AI 가 지금 화면이 무엇인지 판단해 그 화면을 이루는 소스
(화면·컴포넌트·서비스·SQL·API 등)를 찾아 `.atlas/screens/` 에 기록해요. 다음부터 같은 화면을 열면 목록이 바로 떠요. 팀과 공유돼요.

### 네트워크·콘솔 자동 수집

AI 는 화면뿐 아니라 그 탭의 **네트워크 요청과 콘솔 오류**도 읽어요. "저장 버튼이 안 먹어요"의 진짜 원인(API 가 500 을 돌려줬다, 스크립트 오류가 났다)이 거기 있거든요.

- 패널 헤더 표시등: **네트워크·콘솔 수집 중**(초록) / 수집 꺼짐(흐림).
- 수집하는 동안 브라우저가 탭 위에 **"…이(가) 이 브라우저를 디버깅하고 있습니다"** 노란 배너를 띄워요. 브라우저가 강제로 띄우는 표시라 없앨 수 없어요.
  거슬리면 패널 **⚙ → "네트워크·콘솔 자동 수집"** 을 끄세요(그땐 F12 를 열어 둔 동안만 수집해요).
- **붙은 뒤부터** 모여요. 이미 지나간 오류는 한 번 더 재현해야 잡혀요.
- F12 개발자 도구를 열면 확장은 물러나고 개발자 도구가 수집을 맡아요. AI 쪽은 달라지는 게 없어요.

### atlas-react 화면이라면

[atlas-react](../react/README.md) 로 만든 화면은 화면이 등록한 기능(조회·저장 등)을 AI 가 **직접 실행**할 수 있어서 테스트가 훨씬 정확해져요.

## 15. atlas 명령(CLI)

Studio 의 거의 모든 동작은 들어 있는 `atlas` 명령으로도 할 수 있어요(AI 도 같은 명령을 써요). 통합 터미널에서 바로 쳐요.
전체는 `atlas --help`, 각 명령은 `atlas <명령> --help`.

**프로젝트·워크벤치**

```
atlas workbench project | use <id> | new <id>    워크벤치 목록 · 전환 · 추가
atlas workbench apply <템플릿>                    템플릿 적용
atlas workbench export | pack | install          워크벤치 → 템플릿으로 내보내기·묶기·등록
atlas stage list | add | order | remove          단계 관리
```

**작업·실행**

```
atlas activity list                              작업 목록
atlas activity run <id> [-p 키=값] [--agent 이름] 작업 실행 (화면 없이)
atlas activity jobs | runs | resume <runId>      실행 기록 · flow 실행 · 이어 하기
atlas activity set-flow | set-requires | set-input-form   흐름·선행 조건·입력 폼 설정
atlas activity reorder <단계> <id…>              순서 바꾸기
atlas activity chat-action <id> on|off           챗 / 목록에 올리기·내리기
atlas work-items list | add | set-status …       작업 목록
atlas tasks list | add | run <id> [--all]        작업 지시서 · 배치 실행
atlas skill export | check | list | run <이름>   스킬 내보내기 · 점검 · 실행
```

**AI**

```
atlas subagent "<지시>"                          서브에이전트 한 번 실행 → 요약
atlas infer -s "<시스템>" "<입력>"               도구 없이 AI 에게 한 번 묻기 (요약·분류·번역 같은 부품)
atlas agents list | add | remove | resolve       에이전트 프로파일
atlas models list [--refresh]                    모델 목록
atlas accounts …                                 Claude 계정 저장·전환
atlas guide [이름 | 질문]                         사용법 가이드 (없으면 목록, 질문이면 관련 절 검색)
```

**지식·기록**

```
atlas wiki grep <키워드…> | list                 위키 검색
atlas notes list | grep | add | daily …          개인 노트
atlas file-history [--file 경로] [--from …]      파일 변경 이력
atlas lab list | report | feedback               Studio 개선 랩
atlas docs list | read <파일>                    앱에 들어 있는 사용자 문서
```

**도구·구성 요소**

```
atlas tool list | env status                     툴 목록 · 외부 패키지 상태
atlas mcp list | add | remove | enable | disable MCP 서버 (-g = 이 PC 전체)
atlas graph run <파일> | env …                   그래프 실행 · Python 환경
atlas engine install | status | stop | restart   그래프 엔진
atlas agent install | status | stop | restart    에이전트 서버
atlas debug-adapter install | add | list | remove   디버그 어댑터
atlas lsp list | install <id>                    언어 서버
atlas browser-extension install | status         브라우저 확장 폴더 준비
atlas path                                       atlas 실행 파일 위치
```

단축키는 [단축키](shortcuts.md), 안 될 때는 [문제 해결](troubleshooting.md) 을 보세요.
